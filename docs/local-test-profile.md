# Local Test-Profile Workflow

End-to-end checkout smoke test against Stripe / Resend / PriceLabs sandboxes, without touching production credentials.

## Why this exists

The `.env` at the repo root is generated by the **1Password desktop app** (see header in the file). It holds the canonical runtime keys (`STRIPE_SECRET_KEY`, `RESEND_API_KEY`, `HOST_EMAIL`, …) populated with **production** values, plus parallel `*_TEST_*` variants for sandbox values.

Next.js auto-loads `.env` on `pnpm dev`, so a bare `pnpm dev` would point the app at **live Stripe** and real card processing. This workflow overlays the test values onto the canonical names for a single dev process.

## 0) One-time setup

Install the Stripe CLI (needed to forward webhook events to localhost):

```bash
brew install stripe/stripe-cli/stripe
```

You don't need to run `stripe login` if you pass `--api-key` (see step 3).

> **Heads up about 1Password.** The repo's `.env` is a 1Password-managed named pipe. Each time a process opens `.env`, 1Password will prompt you (notification + biometric/touch) to authorise serving the secrets. The human approval step is unavoidable — `scripts/checkout-smoke.sh up` will fail with a "Missing …" error if you don't approve before sourcing. Approve, then re-run.

## 1) Create the local test-profile file

```bash
cp env/test-profile.local.example .env.test-profile.local
```

Then fill `.env.test-profile.local` with sandbox values. If your `.env` already has `*_TEST_*` variants from 1Password, copy each one into the matching canonical key:

| Canonical (used by app code) | Source in 1Password `.env` |
| --- | --- |
| `STRIPE_SECRET_KEY` | `STRIPE_TEST_SECRET_KEY` |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | `NEXT_PUBLIC_STRIPE_TEST_PUBLISHABLE_KEY` |
| `RESEND_API_KEY` | `RESEND_TEST_API_KEY` |
| `HOST_EMAIL` | `HOST_TEST_EMAIL` |

Also set:
- `PRICELABS_API_KEY`, `STUDIO_ICAL_URL`, `ONEBR_ICAL_URL` — same values as production are fine (read-only).
- `NEXT_PUBLIC_SITE_URL=http://localhost:3000` — so Stripe success/cancel redirects come back to dev.
- `STRIPE_WEBHOOK_SECRET` — placeholder for now; you'll replace it in step 3.

## 2) Start local dev with the test profile loaded

```bash
./scripts/dev-test-profile.sh
```

What this does:
- Loads `.env.local` first (if present)
- Overlays `.env.test-profile.local` values on top
- Runs `pnpm dev` with the overlaid environment for this process

Note: the script intentionally does **not** source `.env`. Next.js itself still auto-loads `.env`, but the script's overlay (and Next.js's own `.env.local` precedence) makes sure canonical names point at test values for this process.

## 3) Start Stripe webhook forwarding (separate shell)

Pass the test secret key directly so you don't need an interactive `stripe login`:

```bash
stripe listen \
  --api-key "$(grep '^STRIPE_TEST_SECRET_KEY=' .env | cut -d= -f2-)" \
  --forward-to http://localhost:3000/api/webhooks/stripe
```

Copy the printed `whsec_...` value into `.env.test-profile.local` as `STRIPE_WEBHOOK_SECRET`, then restart the dev server from step 2 so it picks up the new secret.

## 4) Exercise the checkout flow

Either drive the booking UI in a browser, or hit the API directly:

```bash
curl -sS -X POST http://localhost:3000/api/checkout \
  -H "content-type: application/json" \
  -d '{
    "unit":"studio",
    "checkIn":"2026-07-15",
    "checkOut":"2026-07-17",
    "guests":{"adults":2,"children":0},
    "guestName":"Smoke Tester",
    "guestEmail":"you@example.com"
  }'
```

Open the returned `url` and pay with Stripe test card `4242 4242 4242 4242` (any future expiry, any CVC, any ZIP).

## 5) Verify

In the `stripe listen` shell, you should see something like:

```
--> checkout.session.completed [evt_...]
<-- [200] POST http://localhost:3000/api/webhooks/stripe [evt_...]
```

In the dev server log, no `Resend error:` lines means both emails fired — check the guest inbox and `HOST_EMAIL` inbox for confirmation messages.

The browser should land on `/booking/success?session_id=cs_test_...` with a "Booking Confirmed!" page.

## 6) Switch back to normal local env

Stop the dev server and `stripe listen`, then run the default command:

```bash
pnpm dev
```

No `.env.local` edits or renames are needed.
